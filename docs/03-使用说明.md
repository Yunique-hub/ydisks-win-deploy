# 使用说明

> 面向使用者，不需要懂 Go 或命令行。
> 部署完成后的日常操作都在这里。

---

## 一、先打开管理后台

浏览器访问 **<http://127.0.0.1:59188>**

| 项 | 值 |
|---|---|
| 用户名 | `admin` |
| 密码 | 部署时设置的（若没设，见下面的「忘了密码」） |

双击根目录的 **`打开后台.bat`** 也能直接打开。

---

## 二、第一次使用：按顺序做这七步

### 第 1 步：改掉管理员密码

进后台 → 右上角头像 → **系统设置** → 修改密码。

> 初始密码写在 `data\初始管理员凭据.txt` 里，**改完密码就删掉那个文件**。

### 第 2 步：绑定闲鱼账号

**账号管理** → **添加账号** → 用**手机闲鱼 App 扫码**。

- 扫码后账号状态会从「离线」变成「在线」
- 如果平台要求人脸/安全验证，按页面提示在手机上完成
- 可以绑多个账号，每个账号的会话、商品、订单都是隔离的

> ⚠️ **不要**把二维码、Cookie 或账号密码发给任何人。绑定完全在本机完成。

### 第 3 步：同步商品与订单

账号在线后，在 **商品管理** 点「同步」，在 **订单管理** 点「同步」。

这一步把闲鱼上的数据拉到本地，后面的自动化规则才有东西可匹配。

### 第 4 步：准备交付内容（卡密库存）

**卡密库存** → 新建。支持四种类型：

| 类型 | 用途 |
|---|---|
| 文本 | 固定的交付说明（如网盘链接 + 提取码） |
| 批量卡密 | 一行一条，卖出后自动取走一条（发完自动停） |
| 图片 | 交付图片（如二维码、截图） |
| API | 调用你自己的接口取货，返回什么就发给买家 |

**这个是自动发货的核心** —— 没有卡密就没有东西可发。

### 第 5 步：配置自动化规则

**自动化规则** → 新建：选择闲鱼商品 → 关联卡密/规格 → 设置触发条件。

自动化的四个分支（理解了这个就不会配错）：

| 场景 | 行为 |
|---|---|
| 普通商品付款 | 发卡/发货模板 → 按开关确认发货 |
| 多规格商品付款 | **只匹配完整 SKU 组合**的规则，不做部分匹配 |
| 砍价（未开自动免拼） | 「待刀成」阶段不处理，等「待发货」再发卡 |
| 砍价（开了自动免拼） | 「待刀成」只免拼一次，等「待发货」才发卡 |

> ⚠️ **「自动确认发货」是独立开关**。没打开时你能看到发货记录但订单不会自动确认收货。
> 首次用建议先关着，跑通几次再开。

### 第 6 步：配置消息回复

两种，按需配：

**关键词回复**（`关键词回复` 菜单）：买家提到某些词就自动回复。
支持多个表达式、包含/正则匹配、限定商品范围。

**默认回复**（`默认回复` 菜单）：没有命中关键词时的兜底回复。
注意有个「仅回复一次」选项，避免对同一个买家重复刷屏。

**AI 回复**（`系统设置 → AI 回复`）：需要 OpenAI 兼容接口。
两种模式：
- **仅砍价** —— 只在买家砍价时介入，其余走关键词/默认回复
- **全场景客服** —— 所有消息都交给 AI

配完可以用「测试连接」验证链路。

### 第 7 步：配置通知

**通知渠道** 支持：Bark、钉钉、飞书、企业微信、Telegram、邮件、自定义 Webhook。

建议至少配一个。**「需要人工处理」的通知一定要能收到** ——
自动化遇到不确定的状态时会停下来等你，收不到通知就会一直卡着。

## 三、日常怎么用

### 看运行状态

双击 **`状态.bat`**，或者：

```powershell
.\deploy\status.ps1
```

输出示例：

```
  服务进程          运行中（PID 62760）
  运行时长          32 分钟
  监听端口          59188 已监听
  健康检查          通过
  版本            Ydisks Xianyu Helper 1.0.14 (commit 39e766078ca4, ...)
  数据库           E:\...\data\xianyu_data.db（0.57 MB）
  Chromium      就绪（688.9 MB）
  管理后台  http://127.0.0.1:59188
```

### 启动 / 停止

| 操作 | 双击 | 命令行 |
|---|---|---|
| 启动 | `启动.bat`（或 `start.bat`） | `.\deploy\start.ps1` |
| 停止 | `停止.bat`（或 `stop.bat`） | `.\deploy\stop.ps1` |
| 看状态 | `状态.bat`（或 `status.bat`） | `.\deploy\status.ps1` |
| 验证部署 | `验证部署.bat`（或 `verify.bat`） | `.\deploy\verify.ps1 -Password '<密码>'` |

> 两种文件名的入口**行为完全一样** —— 中文名给日常双击用，ASCII 名给脚本/CI 用。
> 每个 `.bat` 都会自动挑 PowerShell：装了 PowerShell 7 就用 7，没装就用系统自带的 5.1。
> 报错时窗口会停住等你按回车，不会一闪而过。

> **不关机就不用停**。服务常驻，自动化规则靠它执行。
> 关掉浏览器不影响服务运行。

> ⚠️ 停止服务时可能要等约 15 秒：上游当前版本不消费「停止标记」文件，
> 脚本会按「写标记 → 等 15 秒 → 关闭窗口 → 强杀」逐级退让。属正常现象。

### 让它开机自启（推荐）

**方式一（推荐）**：双击 **`安装服务.bat`**，弹出 UAC 确认框时点「是」。

**方式二**：用管理员身份打开 PowerShell：

```powershell
.\deploy\install-service.ps1 -Mode install
```

装成 Windows 服务后：开机自动运行、不用登录桌面、不用管窗口。
卸载：`.\deploy\install-service.ps1 -Mode uninstall`（不会删数据）。

### 看日志

| 日志 | 位置 | 用途 |
|---|---|---|
| 服务运行日志 | `logs\server.log` | 业务与 HTTP 记录（JSON 格式）**排查首选** |
| 标准输出 | `logs\server.stdout.log` | 旧版本启动期的报错留档 |
| 运维脚本日志 | `logs\bootstrap.*.log` 等 | 部署/构建/启动/验证过程 |
| 渲染快照 | `logs\rendered-dom.html` | 验证时真实 Chromium 渲染出的页面 DOM |

后台里也有 **日志** 菜单可以看运行日志。

## 四、常见问题

### 忘了管理员密码

```powershell
.\deploy\reset-admin.ps1
```

会自动生成一个新密码并打印出来。**过程中会先停服务再启动**。

想自己指定：

```powershell
.\deploy\reset-admin.ps1 -Password 'MyNewPass123' -Email 'me@example.com'
```

### 双击 .bat 却报一堆看不懂的错

如果看到这种「明明代码没问题却报少花括号」的错误：

```text
Missing closing '}' in statement block or type definition.
Unexpected token ')' in expression or statement.
```

并且报错行里的中文是乱码 —— 那是**脚本文件编码**问题（`.ps1` 少了 UTF-8 BOM，
Windows PowerShell 5.1 会按 GBK 解码导致中文串撕裂），不是你的操作错了。

```powershell
.\tests\test_scripts.ps1     # 检查器会直接点名「缺少 BOM」
```

修复见 [部署手册 · 编码坑复盘](02-部署手册.md)。正常发布的版本不会出现这个问题 ——
CI 与静态检查都会拦住它。

### 命令卡住不返回（服务其实起来了）

如果你把启动脚本的输出接进了管道（例如 `& .\deploy\start.ps1 2>&1 | Out-String`），
可能会一直等不到结束 —— 长驻服务继承了输出句柄。这是已知行为，
改用 `.\deploy\start.ps1 -Foreground` 或直接读 `logs\server.log`。

### 打不开管理后台

1. 双击 `状态.bat` 看服务是否在跑
2. 没跑 → 双击 `启动.bat`
3. 在跑但打不开 → 看 `logs\server.log` 尾部（`logs\server.stdout.log` 是旧版本留下的）

### 账号掉线了

平台会在多种情况下让登录态失效。在 **账号管理** 里点「重新登录」扫码即可。

如果频繁掉线，检查：
- 是不是短时间内做了太多操作（内置节流是为了防这个，别去改）
- 是不是同账号在多个地方同时登录

### 浏览器相关功能异常

登录、滑块、浏览器指纹这些依赖 Chromium（689 MB）。

验证 Chromium 是否就绪：

```powershell
cd E:\codex_my_project\闲鱼
.\deploy\verify.ps1 -SkipRestart
# 看 G 段「服务内 Playwright Chromium 已就绪」
```

丢了就重装（会重新下载约 700 MB）：

```powershell
.\deploy\bootstrap.ps1 -Force
```

### 想看前端改动的效果

**改了前端源码必须重新构建 + 重启服务**：

```powershell
.\deploy\build.ps1      # 会先停服务、构建、再自动启回来
```

浏览器硬刷新（Ctrl+F5）**不够** —— 前端是编译进 Go 二进制的，运行中的进程不会换资源。

### 数据在哪里？怎么备份？

```
data\xianyu_data.db      业务数据（账号、商品、订单、卡密、规则）
data\data.key            敏感字段加密密钥 ★ 必须一起备份
data\uploads\            上传的图片
logs\                    日志
```

> ⚠️ **`data.key` 丢了，已加密的账号凭证就永久无法恢复**。
> 备份要两个一起备。

冷备份（先停服务再拷）：

```powershell
cd E:\codex_my_project\闲鱼
.\deploy\stop.ps1
Compress-Archive -Path .\data -DestinationPath "..\ydisks-backup-$(Get-Date -Format yyyyMMdd).zip"
.\deploy\start.ps1
```

### 想换端口

```powershell
.\deploy\stop.ps1
.\deploy\start.ps1 -Port 8080
```

换成服务模式的话：`.\deploy\install-service.ps1 -Mode install -Port 8080`

### 想从别的电脑访问

默认只监听 `127.0.0.1`（只有本机能访问），这是刻意的 ——
管理后台能操作你的闲鱼账号，暴露出去风险很大。

确实需要时：

```powershell
.\deploy\start.ps1 -BindAddress 0.0.0.0
```

**但必须配套**：防火墙限制来源 IP、前面加 HTTPS 反向代理。
不要直接把它挂在公网上。


## 六、安全红线

1. **管理后台能完全控制你的闲鱼账号** —— 不要暴露到公网，不要设弱密码
2. **`data\data.key` 是凭证解密密钥** —— 泄露等于账号被接管
3. **`data\xianyu_data.db` 含账号凭证** —— 不要发给任何人
4. **不要为了提高速度去改内置的请求节流**（`internal/xianyu/mtop/pacer.go`）
   —— 那是防封号的，不是性能瓶颈
5. **不要同时把同一个闲鱼账号绑到多个管理端** —— 容易触发风控
6. **用真实账号跑自动化前先用小号验证规则** —— 尤其涉及发卡/发货的
