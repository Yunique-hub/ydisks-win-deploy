# 部署手册

## 前置条件

| 项 | 要求 | 说明 |
|---|---|---|
| 操作系统 | Windows 10/11 x64 | 也可在 macOS/Linux 上手工执行等价命令 |
| **Node.js** | **24 或更高** | 构建前端用。`bootstrap` 会检查 |
| Git | 任意近期版本 | 克隆上游源码 |
| Go | **不需要预装** | `bootstrap` 会自动下载便携版（1.26.10，72 MB）到 `runtime\go` |
| PowerShell | **不需要额外安装** | 系统自带的 Windows PowerShell 5.1 就能跑；装了 PowerShell 7 会自动优先用 7 |
| 磁盘 | **≥ 3 GB 空闲** | Go 模块缓存 ~700 MB + Chromium ~700 MB + 源码 235 MB |
| 网络 | 能访问 GitHub / goproxy.cn / npm / cdn.playwright.dev | 首次部署需要 |

**不需要**：Docker、MySQL、PostgreSQL、Redis、Python。
默认使用 SQLite，零外部数据库依赖。

### PowerShell 版本兼容矩阵

| 解释器 | 支持 | 说明 |
|---|---|---|
| Windows PowerShell 5.1（系统自带） | ✅ **基线** | 所有 `.ps1` 保持 5.1 语法兼容；`.bat` 默认走它 |
| PowerShell 7.x（`pwsh`） | ✅ | `.bat` 检测到 `pwsh` 自动优先使用；CI 双版本矩阵跑同一套测试 |

> ⚠️ **`.ps1` 文件必须带 UTF-8 BOM**。5.1 只认带 BOM 的 UTF-8，
> 无 BOM 会按系统 ANSI 代码页（简体中文机器是 936/GBK）解码，
> 中文串被撕裂后报出**与真实问题无关**的语法错误。见下文「编码坑复盘」。

## 一、一键部署

在仓库根目录双击 `一键部署.bat`，或命令行执行：

```powershell
.\一键部署.bat          # 中文名入口
.\deploy.bat            # 纯 ASCII 名等价入口（行为完全一致）
.\deploy\bootstrap.ps1  # 直接调脚本，输出最详细
```

所有 `.bat` 都经 `deploy\run.ps1` 统一引导：

```
.bat  →  run.ps1  →  目标脚本
         ├── 挑解释器：优先 pwsh(7) → 回退 powershell.exe(5.1)
         ├── 控制台输出固定 UTF-8（5.1 默认 ANSI，中文会变 '?'）
         ├── -Elevate：需要管理员权限时走 UAC 提权
         └── 透传退出码
```

入口一览（中文名与 ASCII 名成对存在）：

| 中文名 | ASCII 名 | 作用 |
|---|---|---|
| `一键部署.bat` | `deploy.bat` | 九阶段从零部署 |
| `启动.bat` | `start.bat` | 启动 + 健康检查 |
| `停止.bat` | `stop.bat` | 三级退让停止 |
| `状态.bat` | `status.bat` | 状态总览 |
| `验证部署.bat` | `verify.bat` | 30 项完整验证 |
| `安装服务.bat` | `install-service.bat` | 注册 Windows 服务（自动提权） |
| `打开后台.bat` | — | 打开管理后台页面 |

遇到问题时想看完整输出又不让窗口一闪而过：

```powershell
.\deploy\run.ps1 -Script status -Pause      # 列出可用脚本
.\deploy\run.ps1 -Script start -Pause       # 跑完停在窗口里
```

九个阶段：

```
1/9 检查前置条件（Git / Node 24+ / 磁盘）
2/9 准备便携 Go 工具链（下载 → 校验 SHA256 → 解压到 runtime\go）
3/9 获取上游源码（git clone 到 app\，已存在则 fetch）
4/9 安装前端依赖（npm ci）
5/9 构建（前端 → internal/webui/static，然后编译 3 个 Go 二进制）
6/9 安装 Playwright driver 与 Chromium（约 700 MB）
7/9 初始化数据库与管理员
8/9 启动服务并做健康检查
9/9 打印访问地址
```

**管理员密码**：不传 `-AdminPassword` 会自动生成 20 位强随机密码，
屏幕打印一次 + 写入 `data\初始管理员凭据.txt`。

指定密码：

```powershell
.\deploy\bootstrap.ps1 -AdminPassword 'YourStrongPass123' -AdminEmail 'you@example.com'
```

常用参数：

| 参数 | 作用 |
|---|---|
| `-Port 8080` | 换端口（默认 59188） |
| `-SkipBrowser` | 不装 Chromium（约省 700 MB，但浏览器功能不可用） |
| `-Force` | 强制重下 Go、重克隆源码、重装 Chromium |
| `-NoStart` | 只部署不启动 |

## 二、部署后的目录

```
<仓库根>\
├── app\                      上游源码（git 工作副本，只用于构建）
│   ├── frontend\             React 源码 + node_modules
│   └── internal\webui\static\ 前端构建产物（会被 //go:embed 编进二进制）
├── runtime\                  ★ 工具链与产物（删掉可整体重建）
│   ├── go\                   便携 Go 1.26.10
│   ├── gopath\ gocache\      Go 模块与编译缓存（约 700 MB）
│   ├── bin\                  ★ 构建产物
│   │   ├── xianyu-server.exe   25.1 MB  主服务
│   │   ├── xianyu-tray.exe      6.7 MB  Windows 托盘
│   │   └── browser-install.exe  6.5 MB  Chromium 安装器
│   └── playwright\           Chromium 运行时（约 700 MB）
├── data\                     ★ 业务数据（备份就备份这个）
│   ├── xianyu_data.db        SQLite 数据库
│   ├── data.key              敏感字段加密密钥 ★★
│   └── uploads\              上传文件
├── logs\                     日志
├── deploy\                   部署与运维脚本
│   ├── common.ps1            公共层：路径 / 日志 / 外部命令 / 引号规则 / 探测
│   ├── run.ps1               ★ 统一启动器（挑解释器 / UTF-8 控制台 / 提权）
│   └── bootstrap|build|start|stop|status|verify|reset-admin|install-service.ps1
├── tests\                    脚本静态检查 + 公共层自测（不需要已部署就能跑）
├── docs\                     文档

```

**`runtime\` 可以整个删掉重建**（重新跑 bootstrap）。
**`data\` 绝对不能删** —— 里面是账号、商品、订单、卡密和加密密钥。

## 三、服务管理

### 前台模式（默认，适合日常）

```powershell
.\deploy\start.ps1              # 后台进程 + 健康检查（不用重定向，2.5 秒返回）
.\deploy\stop.ps1               # 停止：写停止标记 → 等 15 秒 → 关闭窗口 → 必要时强杀
.\deploy\status.ps1             # 状态总览
.\deploy\status.ps1 -Json       # 机器可读（给脚本/监控消费）
```

> ⚠️ **不要把 `start.ps1` 的输出接进管道**（`& .\deploy\start.ps1 2>&1 | Out-String`、
> CI 的步骤包装、某些 IDE 任务）。服务是长驻进程，会继承并一直持有调用方的
> stdout/stderr 句柄，调用方永远等不到 EOF —— 表现为「服务起来了但脚本像卡死」。
> 需要看启动细节时用 `-Foreground`，或直接读 `logs\server.log`。

### Windows 服务模式（推荐长期运行）

```powershell
# 方式一：双击 安装服务.bat（会自动弹 UAC 提权）
# 方式二：用「以管理员身份运行」的 PowerShell
.\deploy\install-service.ps1 -Mode install

.\deploy\install-service.ps1 -Mode status
.\deploy\install-service.ps1 -Mode start|stop|restart
.\deploy\install-service.ps1 -Mode uninstall    # 不会删 data\
```

非管理员会话下 `安装服务.bat` 会经 `run.ps1 -Elevate` 走 UAC 重新拉起自己
（用 `-EncodedCommand` 传参，避免中文路径与引号被层层吃掉）。

服务模式下：
- 开机自动运行，不需要登录桌面
- 崩溃自动重启（10 秒 → 30 秒 → 60 秒，24 小时后重置计数）
- 数据与日志仍在本仓库的 `data\` / `logs\`

### 托盘模式

`runtime\bin\xianyu-tray.exe` 提供 Windows 托盘控制器：
状态显示、打开管理页面、打开日志目录、启停后台服务。
托盘与服务是两个进程，可独立使用。

## 四、构建细节

### 为什么构建顺序不能反

```
frontend/src  ──vite build──▶  app/internal/webui/static/  ──//go:embed──▶  xianyu-server.exe
```

Go 用 `//go:embed` 把前端产物**编进二进制**。所以：

1. 必须先构建前端，再编译 Go
2. **改了前端必须重新构建 + 重启服务** —— 运行中的进程不会换已加载的资源
3. 想验证前端改动，浏览器硬刷新不够

### 版本号注入

版本变量在 `xianyu-go/internal/version` 包（**不是 `main`**）：

```powershell
-ldflags "-s -w \
  -X xianyu-go/internal/version.Version=$version \
  -X xianyu-go/internal/version.Commit=$commit \
  -X xianyu-go/internal/version.BuildTime=$buildTime"
```

写成 `-X main.commit` 会**静默无效**，产物永远显示 `dev (commit unknown)`。
`build.ps1` 已处理，版本号优先取 git tag（`v1.0.14` → `1.0.14`）。

验证注入是否生效：

```powershell
.\runtime\bin\xianyu-server.exe -version
# Ydisks Xianyu Helper 1.0.14 (commit 39e766078ca4, built 2026-10-24T13:13:37Z)
```

### 重建时服务会先被停掉

Windows 不允许覆盖正在运行的 exe。`build.ps1` 检测到服务在跑时会：
停服务 → 清理遗留的 `.exe~` → 构建 → 自动重启。
不这样做的话 Go 会写出 `xxx.exe~` 然后改名失败，**产物还是旧的**。

## 五、配置

### 命令行参数（xianyu-server.exe）

| 参数 | 默认 | 说明 |
|---|---|---|
| `-addr` | `:59188` | 监听地址。**`:59188` 是全部接口**，本部署固定用 `127.0.0.1:59188` |
| `-db` | — | SQLite 文件路径（兼容旧用法） |
| `-db-url` | — | 连接 URL，优先级高于 `-db`；也可用 `DATABASE_URL` 环境变量 |
| `-workdir` | — | 服务工作目录（数据与浏览器目录基准） |
| `-playwright-runtime-root` | — | 随安装包分发的 runtime 根目录 |
| `-playwright-driver-dir` | — | Playwright driver 目录 |
| `-playwright-browser-dir` | — | Chromium 缓存目录 |
| `-data-key-file` | — | 加密密钥持久化文件；不存在时自动生成 |
| `-init-admin` | — | 初始化或重置 admin 后退出 |
| `-ensure-admin` | — | 仅在 admin 不存在时创建 |
| `-admin-password` | — | 管理员密码；也可用 `XIANYU_ADMIN_PASSWORD` |
| `-admin-email` | `admin@example.com` | 管理员邮箱 |
| `-no-browser` | — | 禁用 Chromium（浏览器相关能力不可用） |
| `-service` | — | 以 Windows 服务模式运行 |
| `-version` | — | 显示版本信息后退出 |

优先级：`DATABASE_URL` > `-db-url` > `-db`

### 数据库连接示例

```ini
# SQLite（默认，零依赖）
-db data/xianyu_data.db

# MySQL（程序会强制补齐 multiStatements 与 clientFoundRows）
mysql://user:pass@tcp(host:3306)/db

# PostgreSQL
postgres://user:pass@host:5432/db?sslmode=disable
```

切库后在管理后台「系统设置」里改；迁移会在启动时自动执行（`goose`，当前版本 54）。

### Playwright 路径（自定义部署的关键）

**上游 `tools/smoke` 不会传这几个参数** —— 它只传 `-db/-addr/-workdir/-data-key-file`，
所以服务会去默认位置找 Chromium，找不到就退出。

解决办法是设环境变量（服务会读取并应用到子进程）：

```powershell
$env:PLAYWRIGHT_DRIVER_PATH   = "$PWD\runtime\playwright\playwright-driver"
$env:PLAYWRIGHT_BROWSERS_PATH = "$PWD\runtime\playwright\playwright-browsers"
$env:PLAYWRIGHT_SKIP_BROWSER_DOWNLOAD = "1"   # 防止它又去下载
```

其他相关变量：`PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH`（直接指定 chrome.exe）、
`PLAYWRIGHT_NODEJS_PATH`（指定 node）、`PLAYWRIGHT_BROWSER_INSTALLER`（指定安装器）。

## 七、排错

### 编码坑复盘（★ 最坑的一个，报错信息会骗人）

**症状**（真实案例，简体中文 Windows 上双击 `启动.bat`）：

```text
At deploy\start.ps1:40 char:25
+ if (Test-Path $pidFile) {
+                         ~
Missing closing '}' in statement block or type definition.

At deploy\start.ps1:126 char:15
+ Write-Log ' 1) 整?-Foreground 鋦整Ÿ钖...   ← 中文已经是乱码
+              ~
Unexpected token ')' in expression or statement.

    + FullyQualifiedErrorId : MissingEndCurlyBrace
```

**看起来**是脚本少了个花括号；**实际**是文件编码问题。

**根因**：PowerShell 5.1 只在文件**带 UTF-8 BOM** 时才按 UTF-8 解码，
**无 BOM 一律按系统 ANSI 代码页解码**（简体中文机器是 936/GBK）。
UTF-8 的中文串被按 GBK 重新组合后，某些字节对被解成 `?`（不可映射字符），
把字符串字面量的收尾引号连同花括号一起吞掉 —— 于是解析器报的是**结构错误**，
行号还指向看起来完全正常的代码行。

**一分钟判定**：

```powershell
# 前 3 个字节是不是 EF BB BF（UTF-8 BOM）？
$b = [System.IO.File]::ReadAllBytes('.\deploy\start.ps1')
'has BOM = ' + ($b[0] -eq 0xEF -and $b[1] -eq 0xBB -and $b[2] -eq 0xBF)
```

或者直接跑仓库自带的检查器（它会明确报出「缺少 BOM」）：

```powershell
.\tests\test_scripts.ps1
```

**处理**：编辑器里另存为 **UTF-8 with BOM**（VS Code 右下角编码 → Save with Encoding →
UTF-8 with BOM）。批量修：

```powershell
$enc = [System.Text.UTF8Encoding]::new($true)
Get-ChildItem -Path deploy, tests -Recurse -Filter *.ps1 | ForEach-Object {
    $t = [System.IO.File]::ReadAllText($_.FullName)
    [System.IO.File]::WriteAllText($_.FullName, $t, $enc)
}
```

**为什么 `tests\test_scripts.ps1` 以前没拦住它**：检查器用的是 PowerShell 7 的
`Parser::ParseFile`，而 PS7 **能**正常读无 BOM 的 UTF-8，所以永远发现不了这个坑。
现在检查器会额外用**真实的 5.1 解释器**（`powershell.exe -EncodedCommand`）
再解析一遍，CI 也在 5.1 / 7 两个版本上各跑一遍。

### 其它运行时陷阱（同一个修复批次里清掉的）

| 症状 | 根因 | 处理 |
|---|---|---|
| `The term 'if' is not recognized as the name of a cmdlet...` | 5.1 不支持「内联 if 表达式」当命令参数：`Write-Row 'x' (if (...) {...} else {...})` | 先落到变量再传参（见 `status.ps1` 的 `$healthText`） |
| `Cannot overwrite variable args because it is read-only or constant` | `$args` 是自动变量，函数内赋值直接抛错 | 改名（`$buildArgs` / `$serverArgs` / `$requestArgs`）；静态检查已加门禁 |
| 服务起来了，脚本却「卡死」不返回 | `Start-Process -RedirectStandardOutput/-RedirectStandardError` 让长驻服务继承了调用者的 stdout/stderr 句柄，调用方永远等不到 EOF | 启动服务时**不要**加重定向；给脚本输出接管道（`2>&1 \| Out-String`）前先想一下 |
| 中文全变 `?` | 5.1 的管道输出按 ANSI 编码 | 走 `deploy\run.ps1`（已固定 UTF-8），或自己设 `[Console]::OutputEncoding` |

### 服务起不来

```powershell
.\deploy\start.ps1 -Foreground    # 前台运行，直接看报错
```

看日志：`logs\server.log`（业务/HTTP 结构化日志）、`logs\server.stdout.log`（启动期 stderr）。

| 症状 | 原因 | 处理 |
|---|---|---|
| 启动后立刻退出，日志停在「系统尚未初始化」 | 找不到 Chromium 且没加 `-no-browser` | 设 `PLAYWRIGHT_*` 环境变量，或确认 bootstrap 装过 Chromium |
| 端口被占用 | 上次没停干净 | `.\deploy\stop.ps1`，或换 `-Port` |
| `database is locked` | 两个实例共用同一个 SQLite | 确认只有一个 xianyu-server 进程 |
| 健康检查 `database: error` | 数据库文件损坏/无权限 | 看日志；必要时从备份恢复 `data\xianyu_data.db` |
| 停止要等 15–20 秒 | 上游当前版本**没有消费停止标记文件**，只能靠「关闭窗口 → 强杀」兜底 | 属已知行为，不是故障；数据由服务自身的写入事务保证 |

### 构建失败

| 症状 | 原因 | 处理 |
|---|---|---|
| `不是有效的 Win32 应用程序` | 把 `npm.ps1` 当 exe 执行了 | 用 `deploy\common.ps1::Get-ToolPath` 解析，或直接调 `npm.cmd` |
| `flag provided but not defined: -w` | `Start-Process` 没给含空格的参数加引号 | 用 `ConvertTo-ArgumentString` 拼参数 |
| `go: ... connection aborted` | 模块镜像网络抖动 | 重跑；Go 会续传。`build.ps1` 里已配多个镜像兜底 |
| `Cannot bind argument to parameter 'Message'` | `Write-Log ''` 被 `[Parameter(Mandatory)]` 拒绝 | `Write-Log` 已加 `[AllowEmptyString()]` |

### Chromium 问题

| 症状 | 原因 | 处理 |
|---|---|---|
| 服务日志无「playwright chromium 就绪」 | 路径没传对 | 见上文「Playwright 路径」 |
| `Sandbox cannot access executable ... 拒绝访问` | 从含中文/特殊字符的路径直接调 `chrome.exe --no-sandbox` | **服务本身不受影响**（它用 Playwright 自己的启动器，日志可证）；只有手工调用会遇到 |
| `应用程序无法启动，因为应用程序的并行配置不正确` | 用目录 junction 指向 Chromium，破坏了 SxS 清单解析 | **不要对 Chromium 目录建 junction**。需要 ASCII 路径就整个复制 |
| `chrome.exe --dump-dom` 不退出 | Chrome 149 的 `--dump-dom` 在完整 chrome.exe 上不自动结束 | 用 `chrome-headless-shell.exe`（Playwright 自带，`chromium_headless_shell-*` 目录） |

### 上游冒烟测试在 Windows 上必失败

```powershell
cd app
go run ./tools/smoke -bin ..\runtime\bin\xianyu-server.exe
# 冒烟失败: 发送终止信号: not supported by windows
```

**这是上游工具的平台限制，不是部署问题**：
`tools/smoke/process.go:86` 用 `syscall.SIGTERM` 终止子进程，
Windows 不支持 POSIX 信号，也没有 Windows 专用实现。

**功能检查其实全部通过** —— 从服务日志可以证实：

```
{"msg":"数据库已就绪"}
{"msg":"playwright chromium 就绪"}
{"msg":"HTTP 服务启动","addr":"127.0.0.1:51228"}
```

失败点只在最后一步「优雅终止」。用 `deploy\verify.ps1` 代替它 ——
覆盖相同的检查项，并正确处理 Windows 的停止方式。

## 九、卸载

```powershell
# 1. 停服务
.\deploy\stop.ps1
# 或（服务模式）
.\deploy\install-service.ps1 -Mode uninstall

# 2. 想保留数据就只删运行时
Remove-Item .\runtime, .\app -Recurse -Force

# 3. 彻底清空（会丢业务数据，确认后再执行）
Remove-Item .\runtime, .\app, .\data, .\logs -Recurse -Force
```

`install-service.ps1 -Mode uninstall` **不会删 `data\`**。
